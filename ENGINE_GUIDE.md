# RAZOR Engine

RAZOR теперь отделяет бизнес-логику от конкретного бренда. Основной файл настройки — `business_config.json`.

## Как сделать нового клиента

1. Скопируйте подходящий пример из `config_examples/` поверх `business_config.json`.
2. Измените `brand`, `content`, `terminology`, `schedule`, `commerce`, `services`, `staff` и `reviews`.
3. Перезапустите приложение.
4. Используйте отдельную БД для каждого клиента через `DATABASE_PATH`.

В код `app.py` для обычной смены бизнеса лезть не нужно.

## Что настраивается

- название, тип бизнеса, город и описание;
- акцентные цвета и изображения;
- все основные тексты лендинга;
- терминология: мастер / специалист / врач;
- услуги, цена, длительность и описание;
- сотрудники, специализация, опыт и рейтинг;
- время открытия/закрытия, размер сетки слотов, горизонт записи, минимальный запас;
- часовой пояс;
- валюта, шаблон телефона и префикс кода записи;
- отзывы.

## Длительность и конфликты

`duration` у услуги теперь влияет на доступность. Например, при сетке 30 минут услуга на 90 минут занимает три последовательных интервала. Backend проверяет пересечения перед выводом слотов и ещё раз непосредственно перед созданием записи.

## Внешний конфиг

Можно хранить конфиг вне проекта и указать путь через переменную окружения:

`BUSINESS_CONFIG_PATH=/path/to/client.json`

Это удобно, если один код разворачивается для нескольких клиентов.

## Примеры

- `config_examples/beauty_salon.json`
- `config_examples/medical_clinic.json`
- `config_examples/dental_clinic.json`

## Production

Для каждого реального клиента задайте как минимум `APP_ENV=production`, `FLASK_SECRET_KEY`, `ADMIN_PASSWORD` и постоянный `DATABASE_PATH`. SQLite подходит для демо/малой нагрузки при постоянном диске; для масштабирования движок позже можно перевести на PostgreSQL без изменения клиентской модели конфигурации.

## V2: настройка через интерфейс

Теперь основной способ создания нового клиента — не редактирование JSON, а раздел `/admin/settings`.

1. Войддите в `/admin`.
2. Откройте **Настройки**.
3. Заполните бренд, расписание, услуги и сотрудников.
4. Нажмите **Сохранить изменения**.
5. Откройте главную страницу — движок уже использует новую конфигурацию.

JSON остаётся исходным форматом хранения и может использоваться для импорта готовых конфигураций, но ежедневная настройка выполняется через админ-конструктор.

## V2.1: где хранятся настройки

`business_config.json` теперь является стартовым seed-конфигом. При первом запуске он импортируется в хранилище настроек.

- Без `SETTINGS_DATABASE_URL`: SQLite (`DATABASE_PATH`) — удобно для локальной разработки.
- С `SETTINGS_DATABASE_URL`: PostgreSQL — вариант для постоянного production-хранилища настроек.

После первого импорта админ-конструктор сохраняет изменения в БД. Менять JSON вручную для уже запущенного экземпляра больше не требуется.

Проверить backend можно через `/healthz` или прямо в `/admin/settings`.
